In order to be able to tune network and storage needs to requirements, this is an additional delay setting that is added on top of the EVE mandated caching period. Therefore the total wait period will be: $x+additional\_delay$ where $0 <= x <=5$ depending on what part of the caching period the agent starts. 

#+BEGIN_SRC go :tangle go_polling_agent/main.go
var additional_polling_wait = time.Duration(0) * time.Minute
#+END_SRC

This is another tuning parameter that decides how many orders from each side (buy and sell) are recorded. It does not currently check whether there are enough orders in the response to support the supplied order depth, so with large values of $order\_depth$ or regions and items with illiquid markets, requests could fail. The purpose of this tool is to analyze very liquid markets, so this value will be small, and there will be many more orders than the chosen depth.

The return type here is going to be the number of seconds left until the caching period expires.  The window is 5 minutes, but if you come in in the middle of a caching period it will be less.  You want to be synced to the caching window if possible so the data is as fresh as possible, so your additional wait time should be a multiple of 5 for best performance.

The "Expires" header contains the next point in time that new data will be available as a RFC1123 datetime string. We just convert that to a Go time, and then calculate the distance between that future point and the current time. Additionally we add an extra 5 seconds as padding just in case theres some slippage in how long it takes to make the request. We don't want to miscalculate and end up at the very end of the previous caching period and be 5 minutes behind.

#+BEGIN_SRC go :tangle go_polling_agent/main.go

	expires_header := resp.Header.Get("Expires")
	t1, err := time.Parse(time.RFC1123, expires_header)
	currentTime := time.Now()
	distance := int64(t1.Sub(currentTime).Seconds())+5
#+end_src

** Entry Point
*** Function: main()

The main function is simple. Until told to stop, create a timer for the number of seconds to the next caching period (with optional padding), wait for that timer to fire, and then poll the data. The first time through, the timer is not strictly necessary, we just fire it immediately, but it makes the code cleaner to have it still be a timer.

#+BEGIN_SRC go :tangle go_polling_agent/main.go

func main() {
	var nextPoll int64 = 0
	for
	{
		timer := time.NewTimer(time.Duration(nextPoll) * time.Second + additional_polling_wait)
		_ = <-timer.C
		nextPoll = poll_data()
		fmt.Printf("Polling again in %d seconds\n", nextPoll)
	}
}
